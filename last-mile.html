Why AI Code Fails Silently

The "Fail-Soft" Problem

AI-generated code tends to fail quietly — preserving the appearance of functionality while degrading or concealing guarantees. The code looks correct, tests pass, but failure paths are silently swallowed.

  • Reward-shaped behaviour: AI optimises for "plausible over secure" due to RLHF training pressures
  • Coverage blindness: Tests reflect paths you anticipated — AI-generated branches have no coverage and the report stays green
  • Dependency blindness: AI has no awareness of your production environment, APIs, or downstream consumers
  • Temporal gap: Library versions current at training time may now have critical CVEs

AIRA Framework (2025)

15-check inspection framework for detecting failure-untruthful patterns in AI code.

  • Exception handling audit
  • Failure truthfulness checks
  • Boundary condition validation
  • Silent error suppression detection
Key finding: AI-attributed code shows 0.435 high-severity findings/file vs 0.242 in human controls — consistent across JS, Python, and TypeScript.

The Lesson from Fibre: The Commodity Shifts, Value Concentrates

What happened in fibre

  • International bandwidth went from scarce & expensive to abundant & cheap
  • Anyone could buy bandwidth — the "raw material" was commoditised
  • The race became about connecting the last mile — physically reaching the customer
  • Winners differentiated on reliability, speed, value-adds & service
  • Vumatel didn't win by having cheaper backhaul — they won by reaching more homes reliably
Nobody buys submarine cable capacity directly. They buy a fast, reliable connection to their home. The last mile is where the value lives.

What's happening in software

  • Code generation went from scarce & expensive to abundant & cheap
  • Anyone can generate code — the "raw material" is commoditised
  • The race is now about delivering the last mile — getting to production
  • Winners will differentiate on quality, governance, risk management & trust
  • We won't win by generating code faster — we'll win by shipping it safely
Nobody buys AI-generated code directly. They buy working software in production. The last mile is where Dariel lives.

Measuring Last Mile Success

Track what breaks, not just what ships. Lines of code per developer is a vanity metric in an AI-assisted world.

Leading Indicators (Predict Problems)

  • Review coverage ratio — % of AI code getting human review
  • No-review PR rate — work merging without oversight
  • Pipeline success rate — health of automated gates
  • Code churn — fragile changes being rewritten quickly
  • Large branch rate — risk accumulating in big merges

Lagging Indicators (Confirm Impact)

  • Change failure rate — deploys requiring urgent remediation
  • Incidents per deploy — production stability per ship
  • Mean time to recovery — speed of incident resolution
  • Deployment rework rate — code that needs immediate fixing
  • Customer trust score — end-user confidence metrics
Google DORA 2025: AI adoption accelerates velocity — but without robust review and control systems, increased change volume leads to greater instability. More ships going out, more ships needing recalling.
