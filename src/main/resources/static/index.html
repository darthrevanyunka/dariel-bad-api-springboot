Welcome to the Challenge!

This is not your typical API. This API is intentionally broken to simulate real-world production issues you might encounter in an overloaded or poorly designed system.

⚠️ Warning: This API will frustrate you. That's the point! Learn to handle failures gracefully.

🎯 Your Mission

Collect data for 2,000 people by calling three API endpoints:

  • First Names - Get each person's first name
  • Surnames - Get each person's surname
  • Ages - Get each person's age

Compute the Final Value

For each person, calculate: computedValue = firstName + age + surname

Example: Paul Jones, age 38 → Paul38Jones

Submit Your CSV

Create a CSV file with this format:

firstName,surname,age,computedValue
John,Smith,25,John25Smith
Mary,Johnson,30,Mary30Johnson
...
🏆 Winner: First person to submit a correct CSV with all 2,000 records wins! Expected time: ~2 minutes with good resilient code.

😈 Known Issues (Network Chaos Mode Active!)

This API simulates a production system under extreme stress. Expect the following:

Basic Bad Behaviors

Random HTTP Errors: 500, 503, 504 errors (~35% of requests)
Pagination Required: Some endpoints require cursor-based pagination

Network Chaos 🌪️

Random Slowness: 30% of requests take 1-3 seconds to respond
Timeouts: 5% of requests never respond (you MUST set timeouts!)
Variable Rate Limiting: Rate limits vary per client (20-60 req/min) and change randomly!

⚠️ Why This Is Hard:
• Rate limits change mid-session - what worked once may not work again
• Without proper timeouts, your code will hang forever on 5% of requests
• Slow responses look like timeouts - how long do you wait?
• You need: retry logic, exponential backoff, timeout handling, and adaptive rate limiting
