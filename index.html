🎯 Challenge Overview

The Mission

Participants must collect data for 2,000 people by calling three misbehaving API endpoints, compute a value, and submit a complete CSV file. The first person to submit a correct CSV wins! Expected completion time: ~2 minutes with optimal code.

  1. Call three API endpoints to collect:
    • First names
    • Surnames
    • Ages
  2. Compute the final value: firstName + age + surname — example: Paul Jones, age 38 → Paul38Jones
  3. Create a CSV file with all 2,000 records
  4. Submit your CSV for validation
firstName,surname,age,computedValue
John,Smith,25,John25Smith
Mary,Johnson,30,Mary30Johnson
...
(2,000 total records)
😈 The Catch

This API intentionally misbehaves

...to simulate production issues you'll actually run into.

Basic Bad Behaviors

  • Random HTTP Errors (500, 503, 504) — requires retry logic with exponential backoff
  • Cursor Pagination — requires proper pagination handling

Network Chaos 🌪️

  • Random Slowness (1–3s delays) — 30% of requests are slow
  • Timeouts — 5% of requests never respond
  • Variable Rate Limiting — limits change unpredictably (20–60 req/min), per client

Why this is hard

  1. Unpredictable Rate Limits — what worked once might not work again
  2. Timeout Handling — simple retry won't work; you need proper timeout configuration on every request
  3. Slowness vs Errors — is it slow or dead? You need to wait... or retry?
  4. Combined Chaos — all three issues happen simultaneously

💡 Resilient Programming Hints

Patterns you'll need

01 Retry Logic with Exponential Backoff 
async function fetchWithRetry(url, maxRetries = 5) {
  for (let i = 0; i < maxRetries; i++) {
    try {
      const response = await fetch(url, {
        timeout: 60000  // CRITICAL: Set timeout!
      });
      if (response.ok) return response;

      if (response.status >= 500) {
        await sleep(Math.pow(2, i) * 1000); // Exponential backoff
        continue;
      }
      throw new Error(`HTTP ${response.status}`);
    } catch (error) {
      if (i === maxRetries - 1) throw error;
      await sleep(Math.pow(2, i) * 1000);
    }
  }
}
02 Rate Limit Handling (variable rates!) 
if (response.status === 429) {
  const retryAfter = response.headers.get('Retry-After') || 60;
  console.log(`Rate limited. Waiting ${retryAfter}s...`);
  await sleep(retryAfter * 1000);
  // Retry the request
  // WARNING: Rate limit might change on next attempt!
}
03 Timeout Configuration (critical!) 
// Without timeout, your code will hang forever on 5% of requests!
const controller = new AbortController();
const timeoutId = setTimeout(() => controller.abort(), 60000);

try {
  const response = await fetch(url, { signal: controller.signal });
  clearTimeout(timeoutId);
  return response;
} catch (error) {
  if (error.name === 'AbortError') {
    console.log('Request timed out, retrying...');
    // Retry
  }
}
04 Adaptive Rate Limiting 
// Since rate limits change, track your actual limits dynamically
let currentRateLimit = 50;  // Start optimistic
let requestCount = 0;
let windowStart = Date.now();

async function adaptiveRateLimitedFetch(url) {
  if (requestCount >= currentRateLimit) {
    const elapsed = Date.now() - windowStart;
    if (elapsed < 60000) {
      await sleep(60000 - elapsed);
      requestCount = 0;
      windowStart = Date.now();
    }
  }

  try {
    const response = await fetchWithRetry(url);
    requestCount++;
    return response;
  } catch (error) {
    if (error.status === 429) {
      currentRateLimit = Math.floor(requestCount * 0.8);
      console.log(`Rate limit lowered to ${currentRateLimit}`);
      throw error;
    }
  }
}
05 Circuit Breaker Pattern 
class CircuitBreaker {
  constructor(threshold = 5, timeout = 60000) {
    this.failureCount = 0;
    this.threshold = threshold;
    this.timeout = timeout;
    this.state = 'CLOSED';  // CLOSED, OPEN, HALF_OPEN
    this.nextAttempt = Date.now();
  }

  async call(fn) {
    if (this.state === 'OPEN') {
      if (Date.now() < this.nextAttempt) {
        throw new Error('Circuit breaker is OPEN');
      }
      this.state = 'HALF_OPEN';
    }
    try {
      const result = await fn();
      this.onSuccess();
      return result;
    } catch (error) {
      this.onFailure();
      throw error;
    }
  }

  onSuccess() { this.failureCount = 0; this.state = 'CLOSED'; }
  onFailure() {
    this.failureCount++;
    if (this.failureCount >= this.threshold) {
      this.state = 'OPEN';
      this.nextAttempt = Date.now() + this.timeout;
    }
  }
}
🎓 & 🏆

Learning Objectives & Winning Strategy

This challenge teaches

  • Retry logic with exponential backoff
  • Rate limiting & Retry-After headers
  • Cursor-based pagination
  • Graceful error handling
  • Concurrency & parallel requests
  • Data consistency across calls
  • Circuit breakers, timeouts, fallbacks

Winning strategy

  1. Start simple — get one endpoint working first
  2. Add retry logic for random errors
  3. Respect rate limits — throttle, don't hammer
  4. Handle pagination — loop through all pages for ages
  5. Validate locally before submitting
  6. Test incrementally, don't wait for all 2,000 records
🔧 Troubleshooting

Common issues

Random errors won't stop

Implement retry logic with exponential backoff, and cap the maximum retry count to avoid infinite loops.

Getting rate limited

Reduce concurrent requests, implement a request queue, and respect the Retry-After header.

Can't get all ages

The ages endpoint requires pagination — use the cursor from each response until cursor is null or hasMore is false.

CSV validation fails

Check the header exactly: firstName,surname,age,computedValue, verify the formula, and ensure all 2,000 records are present with no duplicates.

Good luck, and remember: the API is meant to frustrate you. That's how you learn! 🚀
